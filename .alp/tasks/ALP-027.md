## Description

`internal/engine/extract.go` `FromURLWithOptions` spans ~L121-938: one ~817-line function
with ~122 `if` branches. It already reads as labeled sequential stages (data: URL
short-circuit, security gate, timeout/redirect setup, cache lookup, fetch+retry, decompress,
charset recovery, SPA/blocked-status handling, HTML handoff), but because they share one
scope, every change forces re-reading the whole function and reviewers cannot see stage
boundaries in diffs. It is the single biggest complexity hotspot in the codebase (file is
1601 lines; next-largest function `fromHTMLInternal` is ~386).

Mechanically extract 2-4 of the most self-contained stages into named private helpers on
the same file (e.g. the cache-lookup/background-refresh block, the fetch+retry loop, the
decompress+charset recovery block), passing state explicitly. No behaviour change, no new
abstractions, no interface — just named stages with narrow signatures. The extensive
existing test net (charset_recovery_test, cache_test, authwall_test, adversarial_test,
snapshot_test...) is the safety harness.

Value: the extraction core is where most future features land (flags, policies, formats);
named stages make those diffs local and reviewable instead of edits into an 800-line scope.
